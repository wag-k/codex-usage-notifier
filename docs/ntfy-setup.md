# 匿名ntfyスマホ通知の設定

Codex Usage Notifierは、公開ntfyサービスを使ってAndroid／iPhoneへ利用枠通知を送れます。ntfyアカウントは不要です。Google OAuthを設定していないWindows-only環境でも、ntfyだけを追加できます。

## 設定手順

1. [ntfy公式サイト](https://ntfy.sh/)から端末用アプリをインストールします。
2. Codex Usage Notifierの設定画面で「スマホ通知（ntfy）」を開き、「生成」を選びます。
3. Topicをコピーし、端末アプリでサーバー`ntfy.sh`の購読Topicとして追加します。Androidでは「Android向け購読リンクをコピー」でディープリンクをコピーし、端末へ安全な方法で渡すこともできます。
4. 「スマホへテスト通知を送信」を選び、端末へ届くことを確認します。
5. 「スマホ通知を有効にする」を選び、設定画面の「保存」を選びます。

テスト通知の成功表示は、ntfy.shがHTTP要求を受理したことだけを意味します。端末で受信できない場合は、Topicの一致、端末の通知権限、バックグラウンド通信、省電力設定を確認してください。

## Topicの安全な扱い

Topicは通知先を識別する秘密情報です。アプリは暗号学的乱数を用いて160ビットのランダム部分を生成し、画面では既定で一部を隠します。Topicを公開リポジトリ、Issue、スクリーンショット、ログへ貼り付けないでください。

Topicは`%LOCALAPPDATA%\CodexUsageNotifier\auth\ntfy-topic.dat`へWindows DPAPIの`CurrentUser`スコープで暗号化して保存します。別のWindowsユーザーでは復号できません。平文Topicは`settings.json`、`state.json`、ログ、Release ZIPへ保存しません。

「再生成」を行うと古いTopic向けの本番配送、保留、再試行は無効になります。新しいTopicを端末で購読し、テスト通知を確認してから通知を再度有効にしてください。旧Topicの購読は端末側で削除できます。

## 送信内容とプライバシー

ntfyへ送るのは、利用枠通知に必要な次の情報だけです。

- 通知種別と段階
- 利用枠の残量、期間、LimitId、Position、Classification
- 次回リセット時刻と残り時間
- 条件成立時刻
- リセット完了の判定理由

複数候補を1件へ集約する場合、通知本文の先頭では週間枠の次回リセットを優先し、各候補の詳細にもそれぞれの次回リセット時刻を表示します。

Codexのプロンプト、会話、ソースコード、Gmail OAuthトークンは送信しません。公開ntfyサービスを利用するため、上記通知情報はntfy.shへ送信されます。より厳格なデータ管理が必要な場合は、ntfyを無効のままWindows通知を使用してください。セルフホストntfyとntfyアカウント認証は現在未対応です。

## 再試行と通知禁止時間

Windows、Gmail、ntfyの配送結果は独立して保存します。ntfyは初回送信と5分後以降の再試行1回の最大2回です。一時的なネットワーク障害、タイムアウト、HTTP 408、429、5xxだけを再試行し、それ以外の4xxや不正Topicは再試行しません。再試行は次の正常な利用枠取得を契機とし、専用タイマーは使いません。

共通の通知禁止時間中は送信回数を増やさず保留します。禁止時間終了後の正常取得で候補がまだ有効な場合だけ送信します。短期回復が閾値未満へ戻った場合、リセット前通知の段階が進んだ場合、利用期間またはTopic世代が変わった場合は古い通知を期限切れにします。

## 実端末での確認

ログに`System.Net.Http.Json`の`FileNotFoundException`が記録される旧版では、HTTP送信前に失敗しています。修正版の配布ZIP全体を新しいフォルダーへ展開して起動し、設定画面からテスト通知を再実行してください。Topicの再生成は不要です。

AndroidまたはiPhoneで、Topic生成、購読、テスト通知受信、アプリ再起動後の設定維持を確認します。自然に通知条件が成立したときは、短期枠回復、週間枠のEarly／Standard／Final／リセット完了、監視障害について、通知を開く前に通知種類・週間枠残量・次回リセット時刻を可能な範囲で確認し、通知を開いてLimitId、位置、分類、期間、条件成立時刻、判定理由を確認します。

Quiet Hours中に送られないこと、終了後に有効な候補だけが届くこと、Topic再生成後に旧Topicへ届かないこと、無効化中に送られないことも確認します。OSごとに通知の表示行数は異なります。実際の利用枠を消費して自然条件を意図的に発生させることは、導入完了の条件ではありません。
